## 1. 背景：MLA 缓存的不是 K/V，而是「潜向量 + RoPE key」

混元采用 **MLA（Multi-head Latent Attention，与 DeepSeek-V3 同款）**。传统 attention 每个 token 要缓存各头的 K、V 两个张量；MLA 则把它们低秩压缩为一个 **512 维的潜向量 `kv_c`**，使用时再经上投影矩阵 `W_UK` / `W_UV` 恢复成各头的 K、V。为了让 RoPE 位置编码能与这种低秩压缩共存，MLA 又把位置信息解耦出来，单独保留一个 **64 维的 RoPE key `k_pe`**，直接与 query 的 `q_pe` 做点积。

因此，无论 INT4 还是 FP8 版本，每个 token 的缓存行都是同一结构：

```
[ kv_c 主体 512 维（量化） | kv_c 的 scale | k_pe RoPE 64 维（不量化） ]
```

两种 dump 的差别只在 **主体用什么精度量化、以及与之配套的 scale 精度和分组粒度**。MLA 不是独立的 K、V 两个 tensor，统计字节数时不要额外乘以 2。

## 2. 逐字节布局

### 2.1 INT4 版（`kv_cache_dtype = int4_mla_sm100`），每 token 448 B

| 字节区间 | 内容 | 元素类型 | 字节占比 |
| --- | --- | --- | ---: |
| `[0, 256)` | 512 个 `kv_c` 量化值，两个 4-bit 值打包为一个 byte，`nibble = q + 8`，q ∈ [-8, 7] | **INT4** | 57.1% |
| `[256, 320)` | 32 个 scale，每个覆盖连续 16 个 INT4 值（512 / 16 = 32） | **BF16** | 14.3% |
| `[320, 448)` | 64 个 `k_pe` RoPE 分量，未量化 | **BF16** | 28.6% |

INT4 以 **无符号 nibble（q + 8）** 存储，不是补码，也不是 NVFP4 浮点编码。

### 2.2 FP8 版（`kv_cache_dtype = fp8_ds_mla`），每 token 656 B

| 字节区间 | 内容 | 元素类型 | 字节占比 |
| --- | --- | --- | ---: |
| `[0, 512)` | 512 个 `kv_c` 量化值 | **FP8 E4M3** | 78.0% |
| `[512, 528)` | 4 个 scale，每个覆盖连续 128 个 FP8 值（512 / 128 = 4） | **FP32** | 2.4% |
| `[528, 656)` | 64 个 `k_pe` RoPE 分量，未量化 | **BF16** | 19.5% |

### 2.3 索引器缓存（两版相同），每 token 132 B，按 64 token 分页

仅部分层（21 层）存在，用于 DeepSeek-V3.2 风格的稀疏注意力索引器（indexer）。它 **不按 token 交错**，而是按页分区存放：

| 页内区间 | 内容 | 元素类型 |
| --- | --- | --- |
| 前 8192 B | 64 token × 128 个 indexer key | **FP8 E4M3** |
| 后 256 B | 64 token × 1 个 per-token scale | **FP32** |

尾页（60 个 token）相应为 7680 B key + 240 B scale，不保存空槽，因此不能直接 reshape 为 `[tokens, 132]` 逐行解析。

### 2.4 各类型的二进制结构（小端）

| 类型 | 位宽 | 结构 | 相对精度（步长） | 动态范围 |
| --- | --- | --- | --- | --- |
| INT4（偏移 8） | 4 | 无符号 nibble，q = nibble − 8 | 16 个量级，≈ 1/8 ≈ 12.5%（相对最大值） | 需外部 scale |
| FP8 E4M3 | 8 | 1 符号 + 4 指数 + 3 尾数 | 2⁻³ ≈ 12.5%，平均 ≈ 6% | 2⁻⁹ ～ 448 |
| BF16 | 16 | 1 符号 + 8 指数 + 7 尾数 | 2⁻⁷ ≈ 0.8%，平均 ≈ 0.4% | 同 FP32 |
| FP32 | 32 | 1 符号 + 8 指数 + 23 尾数 | 2⁻²³ ≈ 1.2e-7 | 同 BF16 |

从压缩的角度看，多字节类型的 **高字节**（符号 + 指数高位）分布集中、可压缩，**低字节**（尾数）接近随机：

- BF16：`hi` = 符号 + 指数高 7 位；`lo` = 指数最低 1 位 + 7 位尾数。
- FP32：`b3` = 符号 + 指数高 7 位；`b2` = 指数最低 1 位 + 尾数高 7 位；`b1` / `b0` = 尾数低 16 位。

## 3. 为什么各部分选用不同精度

### 3.1 `kv_c` 主体用 INT4 / FP8：体量最大，且容错能力最强

- 512 维主体占每行 57%～78% 的字节，是节省显存与带宽的主战场；`k_pe` 只有 64 维，量化它收益有限。
- `kv_c` 是低秩潜向量，使用前要乘以上投影矩阵 `W_UK` / `W_UV`。单个元素的量化误差会在矩阵乘中被 512 个输入线性组合「平均」掉，整体表现为较小的、近似高斯的扰动；这比直接量化每个头的 K / V 更鲁棒，因此可以压到 4 bit。
- **INT4 版**面向 SM100（Blackwell）内核：以 `nibble = q + 8` 的无符号形式存储，解包时只需 `(nibble − 8) × scale`，用移位和减法即可完成，适合在 attention 内核中即时反量化。
- **FP8 版**直接采用硬件原生的 E4M3，Tensor Core 可以直接做 FP8 矩阵乘，无需显式解包；E4M3 自带 4 位指数，本身能表达相对尺度，对异常值更宽容。

### 3.2 scale：INT4 配 BF16 细分组，FP8 配 FP32 粗分组

量化公式为 `x ≈ q × scale`，scale 的精度至少不能低于主体精度，否则主体精度被浪费；同时 scale 的开销又要尽量小。两版的选择都是在这两点之间权衡的结果。

**INT4 → 32 个 BF16 scale（每 16 个值一个）**

- INT4 只有 16 个量级，是最粗的表示。分组越细，每组的 scale 越贴近局部动态范围，越能弥补 4 bit 的粗糙，所以选 16 个值一组。
- BF16 相对误差约 0.4%，远小于 INT4 本身约 6%～12% 的量化步长，精度足够。
- 32 个 scale 若用 FP32 要 128 B，是 BF16 的两倍，会使 scale 开销从 14% 升到 25%，得不偿失。

**FP8 → 4 个 FP32 scale（每 128 个值一个）**

- E4M3 自带 4 位指数、约 2⁻⁹ ～ 448 的动态范围，每个值已经能表达自己的量级，scale 只需做粗粒度的整体缩放，所以可以 128 个值一组，仅 4 个 scale。
- E4M3 只有 3 位尾数，相对误差已达 6%，scale 不能再叠加可观误差；而且 DeepSeek 系列的 FP8 内核约定 per-block scale 为 FP32，与 FP8 GEMM 的累加器精度一致、可直接使用。
- 只有 4 个，FP32 也只占 16 B（2.4%），精度和开销两头都不吃亏。

**索引器 → 每 token 1 个 FP32 scale**

- 128 个 FP8 key 共用一个 scale，分组极粗，scale 必须用最高精度；且每 token 只有 4 B，占比 3%。

### 3.3 RoPE `k_pe` 用 BF16，且两版都不量化：对位置信息最敏感

- `k_pe` 不经过上投影矩阵，直接与 `q_pe` 点积得到 attention 分数的位置项，量化噪声会**直接**改变注意力分布，没有矩阵乘的「平均」效应来缓冲。
- RoPE 是不同频率的 sin / cos 旋转。长序列下，低频分量的微小偏差会在相距很远的 token 之间被放大，损害模型区分远距离位置的能力；本次 dump 的 84k token 长上下文正是最敏感的场景。
- 它只有 64 维，占比 19.5%～28.6%，保留 BF16 的代价可控。这也是 DeepSeek-V3 / vLLM MLA 内核的通行做法：量化 `kv_c`，保留 `k_pe` 高精度。
- 不用 FP32 是因为模型计算本身就是 BF16，再提高精度没有收益，只增加一倍字节。

### 3.4 小结

| 部分 | 类型 | 选择理由（一句话） |
| --- | --- | --- |
| `kv_c` 主体 | INT4 / FP8 | 体量最大、经上投影矩阵平均后容错最强，是显存收益的主战场 |
| INT4 的 scale | BF16 × 32 | 细分组弥补 4 bit 粗糙；BF16 精度相对 INT4 绰绰有余，开销只有 FP32 的一半 |
| FP8 的 scale | FP32 × 4 | E4M3 自带指数可粗分组；数量少所以用 FP32 不心疼，且与 FP8 GEMM 约定一致 |
| `k_pe` RoPE | BF16 × 64 | 直接参与注意力分数、无平均缓冲，长上下文位置精度敏感，维度小保留代价低 |
| 索引器 key | FP8 × 128 | 只用于粗筛 top-k，精度要求低于主注意力 |
| 索引器 scale | FP32 × 1 | 128 个值共用一个，必须高精度，且只占 4 B |

## 4. 对无损压缩的含义

- **INT4 nibble 与 FP8 字节接近均匀分布，几乎不可压缩**（INT4 实测约 3.9 bit / 4 bit）。可压的信息集中在 **BF16 / FP32 的高字节**：同一层内数值量级集中，指数只取少数几个值；相邻 token 的 RoPE 高字节经常相同。
- 因此 block 内字节平面重排（`planes_cm`）的收益来源于 RoPE 与 scale 的高字节平面：
  - INT4 版 BF16 占 43%，重排把压缩率从 1.106× 提升到 1.204×（+8.9%）；
  - FP8 版非 FP8 部分只占 22%，提升幅度较小，从 1.166× 到 1.222×（+4.8%）。
- FP8 版 FP32 scale 的低两个字节（尾数低 16 位）是纯噪声，但只占 1.2%，影响可忽略；索引器的 per-token FP32 scale 反而高度可压（实测约 14×），因为相邻 token 的 scale 非常接近。
- 低比特量化后的数据本身熵已接近满，无损压缩的整体上限约 1.2～1.3×。若需进一步压缩，只能对 BF16 RoPE / scale 的尾数做有损截断，需另行评估精度影响。
